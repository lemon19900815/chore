我看了你给的 Simon Willison 这篇文章。它表面上是在介绍 **Jev**，但我认为真正值得关注的不是 Jev 本身，而是它背后代表的一种 **LLM 产品形态变化：从“生成答案”转向“做决策”**。([Simon Willison’s Weblog](https://simonwillison.net/2026/Sep/21/jev/ "Jev introduces a new shape of LLM—System One, aka Decision Models"))

## 1. 一句话总结

> **Jev 把 LLM 从“会说话的生成器”变成了“概率决策函数”：输入一段非结构化信息，输出一个结构化的概率/分类/评分。**

传统 LLM：

```text
输入文本
   ↓
LLM
   ↓
自然语言答案
```

Jev：

```text
输入文本 / 半结构化数据
          ↓
       Decision Model
          ↓
  0~1 概率 / 分类 / 分数
```

Simon Willison 更倾向于把它叫 **Decision Model（决策模型）**，而不是 TypeSafe AI 所说的 “System One”。([Simon Willison’s Weblog](https://simonwillison.net/2026/Sep/21/jev/ "Jev introduces a new shape of LLM—System One, aka Decision Models"))

# 2. Jev 到底是什么？

Jev 本质上还是一个 LLM，但是它的输出被限制成了非常明确的结构化结果。

目前主要有三种：

### ① Yes / No

例如：

```text
输入：
"Please refund my last payment."

问题：
"Does this message explicitly request a refund?"
```

输出类似：

```json
{
    "probability": 0.97
}
```

也就是：

> 模型认为“这是退款请求”的概率是 97%。

---

### ② Choice

例如：

```text
这条消息应该由谁处理？

billing
technical
other
```

结果不是单纯：

```text
billing
```

而是可以得到：

```text
billing:   0.82
technical: 0.13
other:     0.05
```

因此它其实非常接近一个**语义分类器**。

---

### ③ Score

例如让模型评价一份 bug report 的可复现程度：

```text
0 = 没有复现步骤
1 = 有一些步骤，但缺少关键信息
2 = 有完整步骤、期望结果和实际结果
```

模型输出一个连续分数。

---

# 3. 为什么这个东西有意思？

我认为这是整篇文章最值得关注的地方。

过去我们习惯把 LLM 当成：

> **输入 → 文本 → 输出**

但大量真实业务其实根本不需要文本生成。

例如：

```text
邮件
 ↓
是不是退款请求？
```

```text
用户评论
 ↓
是不是垃圾内容？
```

```text
工单
 ↓
应该分给哪个部门？
```

```text
100 条搜索结果
 ↓
哪个最相关？
```

```text
病历 / 检验结果
 ↓
是否满足某个审核条件？
```

这些任务最终都不是要“写一篇文章”。

最终只需要：

```text
true / false
A / B / C
0.82
```

所以 Jev 实际上是在把：

> **LLM 的“语言能力”封装成一个可以直接嵌入程序的 Decision Function。**

这就是我认为最重要的 insight。

---

# 4. 它和传统机器学习有什么区别？

这点特别值得理解。

传统机器学习：

```text
训练数据
   ↓
训练 classifier
   ↓
spam_classifier
   ↓
spam / not spam
```

Jev：

```text
文本
 ↓
LLM
 ↓
"Is this spam?"
 ↓
0.93
```

最大的区别是：

### 传统 ML

你通常需要：

```text
数据集
↓
label
↓
feature engineering
↓
training
↓
evaluation
↓
deployment
```

而 Jev 更接近：

```text
定义问题
↓
写自然语言 criteria
↓
直接调用模型
```

所以很多原来需要自己训练分类模型的“小型语义任务”，可能可以直接变成一个 prompt。

---

# 5. 更重要的是：它非常便宜

文章中特别强调了成本。

Jev 当时的价格：

> **$0.042 / million input tokens**

而且：

> **output 不收费。**

同时多个问题可以针对同一个 state 并行执行。([Simon Willison’s Weblog](https://simonwillison.net/2026/Sep/21/jev/ "Jev introduces a new shape of LLM—System One, aka Decision Models"))

这意味着：

```text
一个 document
       ↓
 ┌─────┼─────┬─────┐
 ↓     ↓     ↓     ↓
Q1    Q2    Q3    Q4
```

可以同时问：

```text
是不是垃圾邮件？
是不是投诉？
属于哪个类别？
严重程度是多少？
```

而不需要让模型生成四段文字。

# 6. Simon 特别看重的一个应用：Search Reranking

这个其实非常有意思。

传统搜索：

```text
Query
 ↓
BM25
 ↓
100 results
```

BM25 很快，但语义理解有限。

于是可以：

```text
Query
 ↓
BM25
 ↓
Top 100
 ↓
Jev
 ↓
Relevance Score
 ↓
重新排序
```

也就是：

> **便宜的传统算法负责 Recall，Decision Model 负责 Precision。**

这是非常合理的架构。

例如你搜索：

```text
"Windows 下 Asio socket bind 失败"
```

BM25 找出 100 篇可能相关的文档。

Jev 再分别判断：

```text
这篇文章和这个问题有多相关？
```

最终：

```text
Doc A → 0.97
Doc B → 0.91
Doc C → 0.84
...
```

于是得到 reranking。

# 7. 我认为真正值得关注的 Insight：LLM 正在“组件化”

这是我从这篇文章里看到的一个更大的趋势。

过去：

```text
LLM
=
聊天机器人
```

后来：

```text
LLM
=
Agent
```

现在又开始出现：

```text
LLM
=
一个可以被程序调用的智能函数
```

也就是：

```cpp
bool is_spam(string text);

Category classify(string text);

float relevance(string query, string document);

float severity(string report);
```

只不过函数内部不是传统算法，而是 LLM。

---

# 8. 这其实非常像“AI 版函数调用”

文章里面 TypeSafe AI 对 Jev 的描述我觉得非常准确：

> “unstructured state in, typed probabilistic decisions out.” ([Simon Willison’s Weblog](https://simonwillison.net/2026/Sep/21/jev/ "Jev introduces a new shape of LLM—System One, aka Decision Models"))

可以把它理解成：

```cpp
DecisionResult evaluate(State state, Question question);
```

例如：

```cpp
auto result = jev.evaluate(
    ticket,
    "Is this a critical production issue?"
);
```

返回：

```cpp
{
    probability: 0.93
}
```

于是 LLM 不再是你的 UI，而是你的 **业务逻辑基础设施**。

---

# 9. 但 Simon 最大的担忧：Black Box

这也是文章最重要的警告。

普通 LLM 至少还能告诉你：

```text
为什么认为这是垃圾邮件？
```

虽然它的解释未必可靠，但你至少可以看到。

Jev：

```text
文本
 ↓
0.97
```

结束。

你不知道：

```text
到底是什么特征导致 0.97？
```

例如：

```text
spam = 0.97
```

到底因为：

```text
"free"
```

还是：

```text
"click here"
```

还是：

```text
某种语言表达方式
```

你不知道。

Simon 把它称为：

> **Black boxes are back in fashion**

也就是：

**我们好不容易开始讨论 LLM 的可解释性，现在 Decision Model 又把我们推回了更加纯粹的黑盒模型。** ([Simon Willison’s Weblog](https://simonwillison.net/2026/Sep/21/jev/ "Jev introduces a new shape of LLM—System One, aka Decision Models"))

---

# 10. 这直接带来一个非常严重的问题：Bias

比如：

```text
是否应该录用这个人？
```

让模型输出：

```text
0.83
```

看起来特别科学。

但问题是：

```text
0.83
```

里面可能隐藏了：

- 性别偏差
    
- 年龄偏差
    
- 地域偏差
    
- 学校偏差
    
- 语言表达偏差
    
- 训练数据中的历史偏差
    

而最终你只看到了一个：

```text
0.83
```

这比传统 ML 甚至更难调查。

所以 Simon 特别明确地说：

> 不应该拿这种模型直接去做招聘候选人排序。([Simon Willison’s Weblog](https://simonwillison.net/2026/Sep/21/jev/ "Jev introduces a new shape of LLM—System One, aka Decision Models"))

# 11. 因此，Evaluation 反而变得更加重要

这是文章里我认为**最值得开发者记住的一句话**：

> **Decision Model 越便宜，越应该疯狂做 Eval。**

因为传统 LLM eval 可能很贵：

```text
1000 次实验
×
昂贵 LLM
=
很贵
```

Jev：

```text
1000 次实验
≈
几分钱
```

所以你可以非常容易地做：

```text
Prompt A
Prompt B
Prompt C
Prompt D

Dataset 1
Dataset 2
Dataset 3
Dataset 4
```

然后统计：

```text
accuracy
precision
recall
false positive
false negative
bias
```

这其实把 LLM 的使用方式从：

> “感觉这个 prompt 挺好”

变成：

> **“用数据证明这个 decision function 好不好。”**

# 12. 我特别推荐你关注这个变化

结合你之前一直在做的 **C++、IVD 审核、规则表达式、智能审核、MessageBus** 这些东西，我觉得这个方向对你尤其有参考价值。

例如你之前提到的：

```text
HBsAg > 10 AND HBsAb > 10
```

以及：

```text
0 未检查
1 通过
2 不通过
3 跳过
4 跳过
```

这种系统目前通常是：

```text
规则
 ↓
C++ Parser
 ↓
AST
 ↓
Evaluator
 ↓
Result
```

但未来其实可以形成一个混合架构：

```text
                ┌── Deterministic Rules
                │
Input ──────────┤
                │
                └── Decision Model
                         ↓
                  Probability
                         ↓
                  Business Rule
```

例如：

```text
患者信息
检验结果
审核规则
      ↓
Decision Model
      ↓
"是否存在潜在矛盾？"
      ↓
0.91
      ↓
C++ 决策逻辑
      ↓
需要人工审核
```

这样：

**确定性的事情继续用 C++ Rule Engine。**

**模糊的语义判断交给 Decision Model。**

我认为这可能是比“让 LLM 直接做整个审核”更现实的路线。

# 14. 最值得关注的趋势：OpenAI 也已经跟进

这个事情现在已经不是 Jev 的一个小众实验了。

Simon 后续记录到，OpenAI 已经推出了类似 Jev 的 **Decisions API**，同样支持：

- yes/no / predicate
    
- choice
    
- score
    

并且同样采取：

> **输入收费，输出不收费**

OpenAI 的决策模型甚至支持图像输入。([Simon Willison’s Weblog](https://feeds.simonwillison.net/tags/jev/?utm_source=chatgpt.com "Simon Willison on jev"))

所以现在可以把它看成：

```text
           Traditional ML
                │
                │
                ▼
        ┌───────────────┐
        │ Decision Model│
        │               │
        │ Jev           │
        │ OpenAI        │
        │ ...           │
        └───────────────┘
                │
                ▼
          AI Application
```

这说明它很可能会成为 LLM API 的一个正式产品类别，而不是 Jev 的一次性实验。

# 15. 我的最终 Insight

如果把整篇文章压缩成 **5 个观点**，我会这样总结：

### Insight 1：LLM 正在从“聊天”变成“基础设施”

未来你不一定：

```text
调用 LLM → 获取一段文字
```

而可能：

```text
调用 LLM → 获取一个 decision
```

也就是：

```cpp
bool
enum
score
probability
ranking
```

---

### Insight 2：自然语言正在成为一种新的“分类器编程语言”

过去：

```text
写 Python
训练模型
```

现在：

```text
"判断这条消息是否属于退款请求"
```

就可能成为一个模型。

所以 Prompt 不再只是生成文本的指令，而可以成为：

> **业务分类器的定义。**

---

### Insight 3：便宜的小模型 + 大量 Eval，可能比“大模型直接干活”更重要

未来架构可能不是：

```text
一个超级大模型
    ↓
解决所有问题
```

而是：

```text
                 ┌── classifier
                 ├── reranker
Input → Router ──┼── risk scorer
                 ├── extractor
                 └── decision model
```

大量非常便宜的 AI primitives 组成一个系统。

---

### Insight 4：结构化输出 ≠ 可解释

这是最容易被忽略的。

看到：

```json
{
    "probability": 0.93
}
```

**并不意味着系统更科学。**

0.93 只是一个数字，不代表：

```text
93% 的真实概率
```

更不代表：

```text
模型知道自己为什么是 93%
```

所以 Decision Model 的核心工程能力之一将会是：

> **Calibration + Eval + Bias testing**

而不是单纯 Prompt Engineering。

---

### Insight 5：未来最有价值的可能是“确定性代码 + 概率 AI”的混合系统

我觉得这是对你目前做 C++/业务系统最有参考价值的一点：

```text
              ┌──────────────────┐
              │  Deterministic    │
              │  C++ / Rules     │
              └────────┬─────────┘
                       │
                       │
Input ────────────────►│
                       │
              ┌────────▼─────────┐
              │ Decision Models  │
              │ LLM / Jev / ...  │
              └────────┬─────────┘
                       │
                       ▼
              ┌──────────────────┐
              │ Business Logic   │
              │ + Confidence      │
              │ + Human Review    │
              └──────────────────┘
```

**不要让 LLM 取代规则系统；让 LLM 填补规则系统无法处理的“语义判断”部分。**

我认为这可能才是 Jev 这篇文章背后真正值得关注的架构思想。

另外一个很有意思的信号是：Jev 发布不到一周，就已经出现了基于 Qwen 的开源复刻模型和 JevBench；而 Simon 本人也很快做了 `llm-typesafe` 插件。([Simon Willison’s Weblog](https://simonwillison.net/2026/Sep/21/jev/ "Jev introduces a new shape of LLM—System One, aka Decision Models")) **这说明“Decision Model”很可能会像 embedding、reranker 一样，逐渐成为 AI 应用栈中的一种标准组件。**
